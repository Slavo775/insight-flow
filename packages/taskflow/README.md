# taskflow

> A workbench for AI-assisted task lifecycle management — CLI plus a bundled React dashboard.

Taskflow tracks AI-agent task work (specs, implementation, reviews, fixes, pushes, incidents) in sharded JSON files on disk, and serves a live React dashboard that visualizes the pipeline, lifecycle timeline, fix-loop hotspots, and per-task review history.

## Install

```bash
# One-off
npx taskflow init
npx taskflow

# Or globally
npm install -g taskflow
taskflow init
taskflow
```

## Quickstart

```bash
# 1. Initialize in your project (creates taskflow.config.json + workTasks/ + Claude Code skills)
taskflow init

# 2. Create your first task
taskflow create --title "Add auth to dashboard" --type feat --priority high --tags web,auth

# 3. Launch the dashboard
taskflow            # opens http://localhost:6006 in your browser
```

## How it works

```
your-project/
├── taskflow.config.json     # where workTasks live, server port, activity engine
├── workTasks/
│   ├── master.json          # meta + shard index
│   ├── tasks-N00-N09.json   # tasks 0–9
│   ├── tasks-N10-N19.json   # tasks 10–19
│   └── N00-add-auth/        # spec + review files for each task
│       ├── TASK.md
│       └── CHECKLIST.md
└── .claude/
    ├── commands/            # slash commands generated by `taskflow init`
    └── hooks/               # activity engine hook (optional)
```

When you run `taskflow` (or `taskflow ui`):

1. A local HTTP server starts on the configured port.
2. The server serves the bundled React dashboard at `/`.
3. The dashboard reads `workTasks/*.json` from your configured `workDir` via `/api/work-tasks*`.
4. A WebSocket on `/ws` pushes file-change events so the UI updates live as you (or AI agents) edit tasks.

## CLI

```
taskflow                                    # Launch dashboard
taskflow ui [--port N]                      # Same, with optional port override
taskflow init                               # Initialize project

taskflow create --title "..." --type feat|fix|rework [--priority high] [--tags a,b]
taskflow current                            # Show active task
taskflow next                               # Pick next actionable task
taskflow list [--status ready]
taskflow stats                              # Aggregate stats

taskflow implement-start --id N00
taskflow implement-end --id N00 --files "a.ts,b.ts"

taskflow review-start --id N00 [--type ai|human]
taskflow review-end --id N00 --verdict approved|fix-needed [--comment "..."]

taskflow fix-start --id N00
taskflow fix-end --id N00 --files "..." [--comment "..."]

taskflow push --id N00 --commit abc123 --message "..."
taskflow mr-update --id N00 --url "https://..."
taskflow merge --id N00
taskflow done --id N00

taskflow incident-create --id N03 --title "..." --severity critical
taskflow incident-resolve --id N03 --incident INC-001 --rootCause "..." --fix "..."
```

Run `taskflow help` for the full list.

## Configuration

`taskflow.config.json` (created by `taskflow init`):

```json
{
  "workDir": "workTasks",
  "shardSize": 10,
  "projectName": "my-project",
  "rolesDir": ".claude/roles",
  "server": {
    "port": 6006
  },
  "activityEngine": {
    "enabled": true,
    "logFile": ".taskflow-activity.jsonl",
    "maxEvents": 200
  }
}
```

| Key | Default | Purpose |
|-----|---------|---------|
| `workDir` | `"workTasks"` | Directory (relative to your project root) where task JSON shards live. Move/rename this to put task data anywhere you want. |
| `shardSize` | `10` | Tasks per shard file. Affects new shard rollovers, not existing files. |
| `projectName` | inferred from `package.json` | Shown in the dashboard header. |
| `rolesDir` | `".claude/roles"` | Where role spec markdown templates are copied on `init`. |
| `server.port` | `6006` | HTTP/WebSocket port the dashboard listens on. |
| `activityEngine.enabled` | `true` | Stream Claude Code tool activity into the dashboard's activity panel. |
| `activityEngine.logFile` | `".taskflow-activity.jsonl"` | Ephemeral JSONL log file written by the activity hook. Gitignored. |
| `activityEngine.maxEvents` | `200` | Ring-buffer size for the activity feed. |

## Slash commands (Claude Code)

`taskflow init` writes nine slash commands to `.claude/commands/`:

| Command | Purpose |
|---------|---------|
| `/taskmaster` | Create a new task spec |
| `/task-implement` | Implement a task |
| `/task-review` | AI code review |
| `/task-human-review` | Record human review feedback |
| `/task-review-fix` | Fix issues from review |
| `/task-git` | Branch, commit, push, PR, merge |
| `/task-incident` | Track production incidents |
| `/task-request-changes` | Post-implementation change requests |
| `/taskmaster-change` | Edit an existing task spec |

## Programmatic API

```ts
import { startServer, resolveConfig, loadAllTasks } from "taskflow";

const config = resolveConfig();
startServer(config); // or startServer(config, 7000) to override port

const tasks = loadAllTasks(config); // read every shard
```
