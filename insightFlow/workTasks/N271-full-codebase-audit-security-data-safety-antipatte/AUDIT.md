# N271 — Full codebase audit

**Auditor:** Claude Fable 5.1 (`/task-implement N271`), 2026-10-20. Tree: `30277e0` + working tree (branch `feat/N266-authoring-prompt-cookbook`).
**Method:** six parallel read-only verifiers, one per area (dashboard server · master + MCP · core + CLI · agents/hooks/init · React clients · CI/build/tests/deps). Each re-read its area's code, gave a verdict on every `AUDIT-SEED.md` claim with its own file:line, and hunted for new findings. Behaviour claims were checked with `node -e` probes against `dist/` (URL resolution, zod stripping, `replaceAll`, `readBody` UTF-8 split, hook-script quoting), `git cat-file`/`git log` for history, `gh api` for repo/branch/environment settings, `pnpm audit --prod` for advisories, and `grep -c` over existing log files for the malformed-JSON rate. No source file was changed; no server was started against real data; the test suite was not run.
**Paths** are relative to `packages/taskflow/src/` unless they start with `.github/`, `test/`, `templates/`, `scripts/` or are root files. Line numbers are from the current tree.

## 1. Summary — the top 5 risks in plain words

1. **A web page you have open — or anyone on the same Wi-Fi — can install a hook that runs code in your next Claude session.** The dashboard (`:6006`) checks nothing on its write routes: no Origin, no Host, and it answers every request with `Access-Control-Allow-Origin: *`. A cross-site `text/plain` POST to `/api/modules` (kind `hook`, any `command`) followed by `/api/install` lands the command in `.claude/settings.json`. Both servers also listen on every network interface, not just localhost. **(A01–A07)**
2. **The hub is an open proxy to any local port — and even after you lock the dashboard down, the hub still bypasses it.** A request path starting with `//127.0.0.1:<port>/` is proxied to that port (including the hub itself), skipping every guard. Separately, the hub's `/project/<id>/*` route has no gate at all and rewrites `Host` to loopback, so any dashboard-side Host/peer defense is blind to proxied traffic. The gate must live on the hub route. **(A01, A03)**
3. **Task data can be silently lost.** Writes are plain `writeFileSync` (no lock, no temp+rename). A stale in-memory `master.json` plus one `create` zeroes a whole shard file. `events.json` is rewritten on every tool call and erased entirely the first time it fails to parse — which one bare `--data` flag can cause. Older global binaries strip fields newer versions added. **(A08–A10, A25, A27)**
4. **Untrusted input reaches code execution or secret exfiltration in several places.** `events.hooks` from a cloned repo's config runs via `sh -c`. Composer MCP `install` writes hooks and MCP servers with no human confirmation and copies stored API keys into a `.mcp.json` that this very repo has git-tracked. A repo-shipped `insightFlow/agents/task-git.json` can override a built-in agent and drop the locked security modules. Config `rolesDir`/`workDir`/`logFile` can point anywhere on disk. **(A13–A15, A18, A33)**
5. **Your users' agents run weaker prompts than yours do.** `init` writes 10-line stub slash commands that never include `AGENT_SECURITY.md` or the git-permission rules (this repo uses `@ROLE.md` includes, so dogfooding hides it). Cursor skill bodies strip every `@include` instead of inlining it, so Cursor users get zero injection guardrails. And nothing in CI runs the tests — branch protection is empty, publish doesn't test, and Dependabot/secret scanning are turned off on the repo. **(A16, A17, A20–A22)**

### Critical

**A01** [critical][security] `master/server.ts:567-578, 834-847, 580` — Proxy target built with `new URL(rest, targetBase)`; `rest` beginning `//host:port/` (also `\\host:port/`, `//[::1]:port/`) resolves to another origin; the guard checks only that the hostname is loopback. *Any LAN peer (hub binds all interfaces) sends `POST /project/<pid>//127.0.0.1:6100/api/projects/create` → hub proxies to itself from a loopback socket, `Host` deleted, no `Origin` → passes `isTrustedActionRequest` → unauthenticated `/api/fs/list`, `/api/projects/create`, `/start` (spawn), `/api/register`, and any project's `/hub/reregister` (bypasses the `:844` guard). **A02** [critical][security] `dashboard/server/index.ts:764-765, 1064-1140; custom-defs.ts:494-537` — No Origin/Host/Sec-Fetch check on any write route (only `/log` `:1495` and `/hub/reregister` `:804` are gated); ACAO `*` on every response; every POST handler `JSON.parse`s the body regardless of Content-Type. *Cross-site `fetch(..., {method:"POST", mode:"no-cors", body})` is a CORS "simple request" (no preflight). **A03** [critical][security] `master/server.ts:814-874, 579-581` — The `/project/<pid>/*` (and `/p/*`) proxy route has no Host/Origin/Sec-Fetch gate and deletes `Host` before forwarding; the dashboard sees peer `127.0.0.1` and a loopback Host. *With `INSIGHT_FLOW_TRUSTED_HOSTS` unset, a LAN peer or a DNS-rebinding page hits `http://<hub>:6100/project/<name>/api/install` etc.; `:848-851` gives a 404-vs-502 oracle for guessing names.
