# N180 — Rework npm package README as funnel/landing page + fix stale CLAUDE.md dashboard description

**Type:** feat
**Priority:** medium
**Created:** 2026-06-25

## Problem

- The published package README (`packages/taskflow/README.md`, what npm renders at npmjs.com/package/insight-flow) is 975 lines and opens with a **"What's new in 2.0.0"** release-notes block instead of a hook. A stranger landing from npm gets release notes, not a sharp "what is this / why care / how to start." It also has **no badges** and **no prominent link to the docs site**.
- Separately, `CLAUDE.md` describes a **stale pre-2.0 architecture**: a "server-rendered dashboard / no separate React frontend / `dashboard.ts` builds an HTML string with vanilla JS / Socket.IO". Ground truth (verified): the dashboard is a **React + Vite** app (`src/dashboard/client/`, react 18 + react-dom + react-router-dom + styled-components + @xyflow/react; build = `tsup && vite build`) and the live transport moved to **native SSE** (per the 2.0 CHANGELOG; client uses `useDashboardStream.ts`). This misleads every agent session that reads `CLAUDE.md`.

## Goal

1. README opens with a concise elevator-pitch hook (not release notes), so the npm landing reads as a funnel.
2. Badges (npm version, downloads, license) at the top.
3. A prominent **"Full documentation →"** link to https://slavo775.github.io/insight-flow/ near the top.
4. The 60-second CLI quickstart (`npm i -g insight-flow` → `init` → `ui`) stays and is tight.
5. `CLAUDE.md` dashboard/architecture description corrected to React + Vite + SSE.

## Scope

### In scope

- **`packages/taskflow/README.md`:**
  - Replace the opening: lead with the existing one-line pitch + a 2–3 sentence elevator pitch (what / who / why). Demote the **"What's new in 2.0.0"** block to a short line linking the CHANGELOG (`packages/taskflow/CHANGELOG.md`) rather than inlining highlights.
  - Add a badge row under the H1: npm version, npm downloads, license (shields.io). Use the real package name `insight-flow` and license from `package.json`.
  - Add a prominent **"📖 Full documentation → https://slavo775.github.io/insight-flow/"** link high in the README (right after pitch/badges).
  - Keep the existing **Getting started** install + quickstart (steps 1–6); tighten only if it improves time-to-first-success. Do not delete the deeper reference sections (CLI, Configuration, Slash commands, etc.) — this task reshapes the **top of the funnel**, not the whole file.
- **`CLAUDE.md`** (two known stale spots):
  - **Line ~7** ("What This Is"): change "serves a single server-rendered dashboard. There is no separate React frontend — the dashboard is generated by the CLI's HTTP server in `packages/taskflow/src/dashboard/server/`" → describe the React + Vite dashboard (the `src/dashboard/server/` HTTP server serves the built `src/dashboard/client/` React app + JSON APIs).
  - **Line ~41** (`src/dashboard/server/` bullet): replace "the server-rendered dashboard. `dashboard.ts` builds an HTML string with vanilla JS … and Socket.IO for live updates" → the HTTP server serves the built React client + JSON APIs, with **native SSE** for live updates (not Socket.IO).
  - Grep the rest of `CLAUDE.md` for other "server-rendered" / "Socket.IO" / "vanilla JS" / "React frontend" mentions and fix any stragglers.
