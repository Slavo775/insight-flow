# N179 — Document taskflow.config.json configuration reference (docs site)

**Type:** feat
**Priority:** medium
**Created:** 2026-06-24

## Problem

- The Docusaurus docs site (N178) has no reference page documenting the project config file `taskflow.config.json`. Today config is only touched by `cli/config-and-migration.md` (migration *commands* only) and `reference/AGENT_CONFIG.md` (auto-generated, `agents.git.permissions` runtime behavior only). Users have no single place to learn every config key, its default, and what changes when they change it.

## Goal

1. New standalone page `website/docs/configuration.md` documenting `taskflow.config.json` (correct filename — **not** `insightFlow.config.json`).
2. Every key documented by area with: key path · type · default · what it controls · **effect of changing**.
3. Risky-to-change keys carry explicit ⚠️ callouts.
4. An "adjacent configuration" section: global `~/.insight-flow/` files, env vars, ports.
5. A complete copy-paste sample `taskflow.config.json` with every key populated.

## Scope

### In scope

- Create `website/docs/configuration.md` with `sidebar_position` frontmatter so it orders sensibly in the autogenerated sidebar (sibling of `cli/`, `reference/`, etc.). Deliberately top-level — **NOT** under `website/docs/reference/` (that folder is regenerated by `packages/taskflow/scripts/sync-docs.mjs` and would clobber a hand-authored page).
- Document keys from `packages/taskflow/src/core/config.ts` (defaults) + `src/core/types.ts` (schema/optionals), organized by area:
  - Top-level: `workDir`, `shardSize`, `projectName`, `rolesDir`, `editor`, `hooksVersion`
  - `server.port`
  - `activityEngine.*` (`enabled`, `logFile`, `maxEvents`, `phaseMarkers`, `hookEnrichment`, `verbosity`)
  - `notifications.*` (`browser`, `cli`, `sounds.enabled`)
  - `master.*` (`url`, `port`, `standalone`, `startMasterLocally`)
  - `observability.langfuse.*` (`enabled`, `host`, `publicKey`, `secretKey`)
  - `events.*` (`dedupWindowSeconds`, `hooks`)
  - `flows.*` (`defaultFlow`, `byType`)
  - `agents.*` (`extend`, `custom`, `git.permissions.*` — all 10 flags incl. `remoteOps` shorthand)
- ⚠️ "effect of changing" callouts for: `workDir` (repointing after tasks exist orphans the store), `shardSize` (does not re-shard existing files; affects new shards only), `agents.git.permissions.remoteOps: "deny"` (blocks push/forcePush/deleteBranchRemote/createPR unless individually overridden).
- "Adjacent configuration" section: global config under `~/.insight-flow/` (`master.lock`, `master.json`, `batch-ui.json`, session markers), env vars (`LANGFUSE_PUBLIC_KEY`/`LANGFUSE_SECRET_KEY`/`LANGFUSE_HOST`/`LANGFUSE_BASEURL`, `INSIGHT_FLOW_NO_OPEN`, `CLAUDE_SESSION_ID`), and ports 6006 (dashboard) / 6100 (master).
- Source-of-truth note at top pointing at `packages/taskflow/src/core/config.ts` + `src/core/types.ts`.
- Complete sample `taskflow.config.json` (every key populated) as a copy-paste starting block.
- Cross-links to `cli/config-and-migration.md` and `reference/AGENT_CONFIG.md` (don't duplicate git-permissions runtime protocol).

### Out of scope

- CLI flags / per-invocation overrides — link to `cli/` docs, do not re-document here.
- Any change to the config schema, defaults, or code in `src/core/`.
- Auto-generating the page from the Zod schema (manual page for now; source-of-truth note covers drift).
- Editing `reference/AGENT_CONFIG.md` (auto-generated) or its root source.

## Implementation plan
