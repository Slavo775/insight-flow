## Human Review — Round 3

**Reviewer:** Human (Project Owner)
**Date:** 2026-06-24
**Verdict:** fix-needed

### Summary

Framing fix: the docs should make clear that task creation and most lifecycle
commands are **driven by the agents**, not run manually by the user day-to-day. The
agent works *with* the user — the user doesn't normally type `create`/`current`/etc.
Getting Started should reflect this, and the agent-oriented CLI commands should be
called out as such (while still noting the user *can* run them).

### Verbatim feedback

> create my first task should be like via cli or run / taskmaster command no? and also
> we shoud document that creating tasks and all this stuff is mainly for the agents and
> agent working with this user no need to run manually command for creating the tasks so

> tasks current next list statsand so on we should add theere to subsection, information
> about this is mainly for the agents not for the daily use of user not neccesarly mean

### Blockers

1. **Getting Started → "Create your first task".** Present task creation as **either**
   running the CLI (`insight-flow create …`) **or** the `/taskmaster` agent command —
   and make clear the agent path is the normal one. (Ref:
   `/docs/getting-started#2-create-your-first-task`.)
2. **Document the agent-driven model.** State plainly that creating tasks and running
   the lifecycle is **mainly done by the agents** working with the user — the user does
   **not** need to run creation/lifecycle commands manually. Add this to Getting Started
   (and it belongs in Overview framing too).
3. **Flag agent-oriented CLI commands.** For commands that are mainly for the AI/agents
   (e.g. `create`, `current`, `next`, `list`, `stats`, and similar), add a note /
   subsection clarifying these are **primarily for the agents, not the user's daily
   use** — while noting the user *can* still run them.

### Suggestions (non-blocking)

- Consider a short, reusable "Agent-driven — you usually don't run this by hand"
  callout/badge applied consistently across the agent-oriented CLI groups.

### Notes

- This is a content/framing change only — no infrastructure changes requested.
- Pairs naturally with the Round-2 AI non-blocking nits (garbled `cli/index.md`
  sentence, transitions "Via" softening) if the fixer wants to clear those in the same
  pass — at the human's discretion.
