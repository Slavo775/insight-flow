# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Insight Flow is a CLI workbench for AI-assisted task lifecycle management. The `insight-flow` binary owns task state (JSON files under `workTasks/`) and serves a single server-rendered dashboard. There is no separate React frontend — the dashboard is generated by the CLI's HTTP server in `packages/taskflow/src/dashboard/server/`.

## Commands

```bash
# Build the insight-flow package (CLI + dashboard + folded-in master — one package)
pnpm build

# Same thing, invoked directly in the package
pnpm --dir packages/taskflow run build

# Pack the npm tarball
pnpm pack:taskflow

# Run the CLI locally against the playground sandbox
pnpm play                                # → http://localhost:6006

# From inside the playground or any insight-flow project
insight-flow ui                          # → dashboard (auto-starts master on :6100)
insight-flow stats                       # → CLI commands (see TASK_*_ROLE.md)
```

Package manager: **pnpm**. The repo is a workspace; `packages/taskflow` is the publishable package, `playground/` is a sandbox.

## Architecture

**One package, separated by concern.** Everything ships in `packages/taskflow` (published as `insight-flow`); `src/` is split into module folders (N81):

- **`src/core/`** — shared domain: `types.ts`, `schema/`, `storage.ts`, `config.ts`, `global-config.ts`, `paths.ts`, `spec.ts`. Everything depends on `core`; `core` depends on nothing else in `src/`.
- **`src/cli/`** — `cli.ts` (the `insight-flow` bin) + `commands/*.ts`. Subcommands: `create`, `current`, `next`, `next-review`, `next-fix`, `stats`, `list`, `show`, `implement-{start,end}`, `review-{start,end}`, `fix-{start,end}`, `push`, `mr-update`, `merge`, `done`, `change-{request,start,end}`, `next-change`, `incident-{create,status,resolve,list}`, `migrate`, `migrate-reviews`, `prompt-build`, `init`, `ui`, `master`.
- **`src/dashboard/server/`** — the server-rendered dashboard. `dashboard.ts` builds an HTML string with vanilla JS (Kanban / timeline / detail panel); `index.ts` is the Node HTTP server: dashboard at `/`, JSON at `/api/work-tasks/*` (hydrating per-task `reviews.json` / `incidents.json` side files into shard responses), activity at `/api/activity`, and Socket.IO for live updates.
- **`src/master/`** — the multi-project overview server, folded in from the former `insight-flow-master` package (N81). Runs via `insight-flow master`; `insight-flow ui` auto-starts it (`insight-flow master --port 6100`). Self-contained: its own lock at `~/.insight-flow/master.lock`, config, and in-memory registry.
- **`src/agents/`** — agent/hook glue: `agents.ts`, `cursor-hooks.ts`, `hook-parse.ts`, `*-hook.ts`, and `init/` (role/skill scaffolding).
- **`src/index.ts`** — the public API barrel (the package's `exports["."]`).

**Storage layout (`workTasks/`)**

- `master.json` — workspace metadata (next ID, current task ID, shard list, next incident ID).
- `tasks-N00-N09.json`, `tasks-N10-N19.json`, … — shards of 10 tasks each. Each Task carries summary fields (`reviewCount`, `lastReviewVerdict`, `openIncidentCount`) but **not** the full review/incident history.
- `N<XX>-<slug>/TASK.md`, `CHECKLIST.md`, `REVIEW.md` — per-task documentation, scaffolded by `insight-flow create` from `packages/taskflow/templates/task/*.tpl`.
- `N<XX>-<slug>/reviews.json`, `incidents.json` — per-task side files (schema v2). Mutations read/write these; `recomputeTaskSummary` updates the lean fields on the shard's Task.

**Data model:** `packages/taskflow/src/types.ts` defines `Task`, `Review`, `Incident`, `Push`, etc. Tasks flow `ready → in-progress → implemented → reviewing → approved | fix-needed → fixing → fixed → pushed → merged`. Statuses also support change-request workflows (`changes-requested`, `changes-implementing`, `changes-implemented`) and incidents.

**Schema validation:** `packages/taskflow/src/schema/index.ts` (Zod). Every read/write through `storage.ts` validates against these schemas.

**Agent roles:** The 9 `TASK_*_ROLE.md` / `TASKMASTER_*_ROLE.md` files at repo root drive Claude Code slash commands (`/task-analyze`, `/taskmaster`, `/task-implement`, `/task-review`, `/task-review-fix`, `/task-human-review`, `/task-request-changes`, `/task-incident`, `/taskmaster-change`, `/task-git`). `/task-analyze` runs **before** `/taskmaster` — it challenges weak briefs, surfaces alternatives, and only after the human confirms a path hands off to `/taskmaster` and writes an `ANALYSIS.md` audit trail into the new task folder. Shared rules live in `AGENT_ENFORCEMENT.md` + `AGENT_PROTOCOL.md`. Host-specific PR API examples live in `PR_API.md` (technology-agnostic — examples only, no shipped defaults). The `packages/taskflow/scripts/sync-role-templates.mjs` script keeps `packages/taskflow/templates/roles/` in sync with the canonical root files before publish.

**Technology agnosticism:** insight-flow's agent prompts contain **no** specific package-manager, language-toolchain, or git-host commands. Project-specific commands (typecheck / lint / test / PR-create / comment-fetch / etc.) are user-supplied via the `agents.extend` mechanism shipped in N12. See "Extending agents with project-specific commands" below.

## Extending agents with project-specific commands

When `insight-flow init` runs in a consumer project, it scaffolds role files + commands but ships **zero technology assumptions**. Add your stack-specific commands to `taskflow.config.json`:

```jsonc
{
  "agents": {
    "extend": {
      "task-implement":    ["After implementation, run the project's quality gates."],
      "task-review-fix":   ["Re-run quality gates after every blocker fix."],
      "task-git":          ["For PR creation, run the project's host CLI."]
    }
  }
}
```

Each string is appended to the loaded prompt for that agent. Worked examples follow — **as user-supplied content, not shipped defaults**:

**TypeScript + pnpm + GitHub:**

```jsonc
"agents.extend": {
  "task-implement":  ["Run `pnpm typecheck && pnpm lint && pnpm test` before marking implemented."],
  "task-git":        ["For PR creation: `gh pr create --title \"<title>\" --body-file <path>`. Record URL via `gh pr view --json url -q .url`."]
}
```

**Python + uv + GitLab:**

```jsonc
"agents.extend": {
  "task-implement":  ["Run `uv run mypy . && uv run ruff check . && uv run pytest` before marking implemented."],
  "task-git":        ["For MR creation: `glab mr create --title \"<title>\" --description-file <path>`."]
}
```

**Go + GitHub:**

```jsonc
"agents.extend": {
  "task-implement":  ["Run `go vet ./... && golangci-lint run && go test ./...` before marking implemented."],
  "task-git":        ["For PR creation: `gh pr create --title \"<title>\" --body-file <path>`."]
}
```

If `agents.extend` is empty for an agent, that agent runs with the canonical (technology-agnostic) prompt only and will note in its report that the relevant step was skipped.

## Code Style

- TypeScript strict mode enabled in `packages/taskflow/tsconfig.json`.
- No ESLint / Prettier configured at the workspace root — keep diffs minimal and follow the existing two-space indent + double quotes used in `packages/taskflow/src/`.
- Tests: `pnpm --dir packages/taskflow test` runs the init integration tests via `node:test`.

## Task tracking CLI

Task tracking is the `insight-flow` binary published from `packages/taskflow/`. From the repo root, run as `insight-flow <command>` (or `npx insight-flow <command>`). Install once with `npm install -g insight-flow`. See `packages/taskflow/README.md` and the `TASK_*_ROLE.md` files for command reference.

## Task System

Tasks are tracked in `workTasks/` as sharded JSON files. Use the insight-flow CLI or slash commands to manage them.

## Commands

```bash
insight-flow create --title "..." --type feat|fix|rework --priority high|medium|low --tags a,b

insight-flow list                       # List all tasks
insight-flow stats                      # Aggregate statistics
insight-flow next                       # Pick next actionable task
insight-flow                            # Launch dashboard at http://localhost:6006
```

## Slash Commands (Claude Code Skills)

| Command | Purpose |
|---------|---------|
| `/task-analyze` | Pre-taskmaster strategist: challenge the brief, propose alternatives, then hand off to /taskmaster |
| `/taskmaster` | Create a new task spec (TASK.md + CHECKLIST.md) |
| `/task-implement` | Implement a task from its spec |
| `/task-review` | AI code review of implemented task |
| `/task-human-review` | Record human review feedback |
| `/task-review-fix` | Fix issues from review |
| `/task-git` | Branch, commit, push, PR, merge |
| `/task-incident` | Track production incidents |
| `/task-request-changes` | Request post-implementation changes |
| `/taskmaster-change` | Modify an existing task spec |

## Task Lifecycle

```
ready -> in-progress -> implemented -> reviewing -> approved -> pushed -> merged
                                          |
                                     fix-needed -> fixing -> fixed -> (re-review)
```

## Conventions

- Task IDs: N00, N01, N02, ...
- Task folders: `workTasks/Nxx-short-title/` containing TASK.md + CHECKLIST.md
- Branches: `<type>/Nxx-short-title` (e.g., `feat/N00-add-auth`)
- Commits: conventional commits (feat, fix, refactor, docs, chore, etc.)
- Tracker commands: `insight-flow <command>` (run `insight-flow help` for the full list)
