# N08 — Move role definitions into taskflow package and scaffold them via init

**Type:** feat
**Priority:** medium
**Created:** 2026-05-20

## Problem

Per REVIEW*ANALYSIS.md § 3 ("UX & Usability") and § 5 Phase 2.2, the `init` command is sparse — it doesn't scaffold the `TASK*\*\_ROLE.md`role specifications that drive every agent in the system. A new user running`insight-flow init`gets an empty workspace and must manually copy roles from this repo, which defeats the purpose of distributing the package on npm. The role definitions should ship with the package as templates and be copied into the consumer's repo on`init`.

## Goal

1. All 8 role files (`TASKMASTER_ROLE.md`, `TASKMASTER_CHANGE_ROLE.md`, `TASK_IMPLEMENTER_ROLE.md`, `TASK_REVIEWER_ROLE.md`, `TASK_REVIEW_FIXER_ROLE.md`, `TASK_REQUEST_CHANGES_ROLE.md`, `TASK_HUMAN_REVIEW_ROLE.md`, `TASK_INCIDENT_ROLE.md`) live in `packages/taskflow/templates/roles/` and ship with the published package.
2. `insight-flow init` copies these role files into the consumer repo root (or a configurable subdirectory).
3. `init` does NOT overwrite existing role files without explicit `--force`.
4. The Claude Code skill files (`.claude/skills/*.md`) that map to these roles are also scaffolded.
5. The source-of-truth roles in the project root are removed in favor of the package templates (and the package is added to the repo's own root via `init` or a symlink so this repo dogfoods its own distribution).

## Scope

### In scope

- `packages/taskflow/templates/roles/` — populate with the 8 role files.
- `packages/taskflow/src/init/index.ts` — extend to copy role templates.
- `packages/taskflow/package.json` — `files` field must include `templates/`.
- Root repo: roles get scaffolded from the package (delete duplicate copies once dogfooding works).
- `.claude/skills/` scaffolding (if `init` already generates these — extend to cover all 8).
- README updates so new users know roles are scaffolded.

### Out of scope

- Adding new roles (e.g., the "Orchestrator" gap from § 4) — separate task.
- Changing role file contents — pure relocation + scaffolding.
- Updating commands in role files to use `insight-flow` ([[N05]]).

## Implementation plan

1. **Copy roles into the package templates**
   - `cp TASK_*_ROLE.md TASKMASTER*_ROLE.md packages/taskflow/templates/roles/`.
   - Confirm `packages/taskflow/templates/roles/` is no longer empty.
2. **Extend `init` to copy templates**
   - In `packages/taskflow/src/init/index.ts`, after the existing init logic, walk `templates/roles/` and copy each file to the consumer repo root.
   - Skip files that already exist unless `--force` is passed.
   - Print a summary: `created: TASK_IMPLEMENTER_ROLE.md`, `skipped (exists): TASKMASTER_ROLE.md`, etc.
3. **Resolve template path at runtime**
   - Use `import.meta.url` + `fileURLToPath` to locate `templates/` relative to the compiled binary, not relative to `process.cwd()`.
   - This must work both in dev (`pnpm dev`) and after `pnpm pack` / `npm install -g`.
   - Coordinate with [[N10]] on path resolution conventions.
4. **Ensure templates ship with the package**
   - `packages/taskflow/package.json` `"files"` array must include `"templates"` and `"dist"`.
   - Run `pnpm --filter insight-flow pack` and inspect the resulting tarball to confirm role files are present.
5. **Scaffold `.claude/skills/` entries**
   - If `init` already creates skills (per memory: "Taskflow init successfully creates Claude Code skills and CLAUDE.md"), extend it so each of the 8 roles has a matching skill file.
6. **Dogfood**
   - Delete the role files from the repo root.
   - Run `insight-flow init --force` from the repo root and confirm the roles reappear with identical content.
   - `git diff` should show only the path change + possibly a `--force` flag note.
7. **Update package README**
   - Document `insight-flow init` and what it scaffolds.
8. **Smoke test in a clean directory**
   - `cd /tmp && mkdir test-init && cd test-init && npx insight-flow init` and confirm the role files appear.

## Verification

- `ls packages/taskflow/templates/roles/` lists all 8 role files.
- `insight-flow init` in an empty directory creates all 8 role files at the directory root.
- `insight-flow init` in a directory that already has one role file skips that one (or warns, depending on policy) and creates the others.
- `pnpm --filter insight-flow pack` produces a tarball whose `templates/roles/` contains all 8 files.
- The repo's own root has no duplicate copies of the role files (they live only in `packages/taskflow/templates/roles/`); if dogfooding requires them at the root, they are regenerated by `init`.
