## Blockers

1. **N71 implementation absent from release branch & tag `v0.13.0`** — `packages/insight-flow-master/src/overview.ts`.

   **Why:** The `packages/taskflow/CHANGELOG.md` 0.13.0 entry states "`packages/insight-flow-master/src/overview.ts` now computes `isLive = ...` inline in `renderCard` and gates `statusCls`, `claudeBadgeCls`, and `claudeBadgeLabel` on it … Removed entirely: `.conn-badge` / `.conn-live` / `.conn-stale` / `.conn-down` CSS rules, the `badgeInfo()` helper, the `data-badge` markup … and the `refreshBadges()` function + its 30 s `setInterval`." That work exists in the working tree (`grep "isProjectLive" overview.ts` → 3 matches at lines 128 / 210 / 268, `// N71: gate every claudeStatus-driven visual on liveness` comment present) but `git log -- packages/insight-flow-master/src/overview.ts` shows the last commit touching the file is `d7f3ba4 feat(N68)`. `git status` reports `overview.ts` as `modified, unstaged`. The release commit `57dcb66` (= tag `v0.13.0`) does not include the file. `git diff origin/main -- packages/insight-flow-master/src/overview.ts` shows the same — the N71 diff is present only relative to working tree, not relative to `origin/main` or HEAD.

   **Fix:** On this branch, stage and commit `packages/insight-flow-master/src/overview.ts` (it is the only N71 source-of-truth change). Suggested commit: `fix(overview): N71 — gate claudeStatus visuals on liveness, drop live/down badge`. Then force-update the `v0.13.0` git tag to the new commit (`git tag -f v0.13.0 && git push -f origin v0.13.0`) so the tag points at a release commit that actually contains every change the CHANGELOG advertises. Also push the new commit to PR #49. The npm tarball does **not** need a republish — `insight-flow` doesn't bundle master, so the 0.13.0 npm release is correct as-is. (If you prefer not to rewrite the tag, the alternative is to remove the N71 claim from the 0.13.0 CHANGELOG entry and defer N71 to 0.13.1, which is honest but loses the released-as-one-bundle framing.)
